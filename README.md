# LiveShop 🛍️ — لایو شاپ با قیمت ثابت

اپلیکیشن «لایوکامرس» فارسی و راست‌چین (RTL) با تم تیره — فروشنده زنده کالا را نشان می‌دهد و توضیح می‌دهد و خریدار همان لحظه با **قیمت ثابت** می‌خرد؛ با پرداخت امانی (escrow)، بومی‌سازی‌شده برای ایران (تومان، ارقام فارسی، ارسال تیپاکس/پست/پیک، کیف پول با درگاه شبیه‌سازی‌شدهٔ زرین‌پال/آیدی‌پی).

> **نسخهٔ فعلی:** v1.5.1 (سختی‌سازی امنیتی بک‌اند فاز ۱ — تست‌محور؛ UI دست‌نخورده) — تاریخچهٔ کامل تغییرات در [`CHANGELOG.md`](./CHANGELOG.md)
> **قانون طلایی پروژه:** هیچ صفحه/قابلیت موجودی حذف یا خراب نمی‌شود؛ کلیدهای پیکربندی فقط آنها را خاموش/روشن می‌کنند.

## 🗄️ بک‌اند (از backend-phase-1)

دیتابیس پروژه **PostgreSQL** است و API واقعی زیر پیشوند `/api/v1` سرو می‌شود (ورود با OTP + API کالا/شو — قرارداد کامل: [`docs/api-spec.md`](./docs/api-spec.md)):

```bash
bun run postgres        # Postgres 17 محلی (بدون نصب سیستم‌عاملی) — یا DATABASE_URL خودتان را بدهید
bun run db:deploy       # اعمال migrationها (شامل قیود stock>=0 و یک‌پین-در-هر-شو)
bun run db:seed         # دادهٔ دموی فارسی (فروشندگان/کالاها/شوها + کیف پول دمو)
```

راهنمای کامل راه‌اندازی، جریان OTP و نمونه‌ها: [`docs/BACKEND.md`](./docs/BACKEND.md)
UI همچنان روی دیتای mock خودش کار می‌کند؛ اتصال فرانت‌اند به این API مرحلهٔ فازهای بعدی است.

### تست‌های امنیتی سرور

```bash
bun run test:server     # ۱۷ تست امنیتی روی یک Postgres واقعی (اسکیمای جداگانهٔ liveshop_test — دیتای dev دست‌نخورده)
```

هر تست طوری نوشته شده که قبل از اصلاح شکست می‌خورد و بعد از آن پاس می‌شود (۲۰۰ درخواست/مسابقهٔ هم‌زمان، پنجرهٔ نرخ با زمان شبیه‌سازی‌شده، reuse توکن و …).

### IP کاربر و TRUSTED_PROXY

محدودیت‌های نرخ (OTP) به IP واقعی کاربر وابسته‌اند. قرارداد اعتماد از v1.5.1:

| محیط | هدر `x-forwarded-for` | تنظیم |
| --- | --- | --- |
| پشت گیت‌وی Caddy این پروژه | Caddy مقدار کلاینت را **بازنویسی** می‌کند (نه اضافه) با آدرس واقعی سوکت → قابل اعتماد | `TRUSTED_PROXY="true"` در `.env` |
| بدون پراکسی / در معرض مستقیم | ساخته‌شدنی توسط کلاینت → **نادیده گرفته می‌شود**؛ به‌جایش `x-real-ip` سطح اتصال یا `local` | خالی بگذارید |

- `TRUSTED_PROXY=true` را فقط وقتی بگذارید که اپ **هرگز** مستقیم (بدون Caddy/پراکسیِ بازنویسی‌کننده) در دسترس نباشد؛ در غیر این صورت کلاینت می‌تواند با هدر جعلی محدودیت per-IP را دور بزند.
- Caddyfile این پروژه با `header_up X-Forwarded-For {remote_host}` مقدار را **set** می‌کند (جایگزینی کامل، نه append مثل رفتار پیش‌فرض Caddy) — زنجیرهٔ جعلیِ کلاینت هرگز به اپ نمی‌رسد.

## 🚀 نصب و اجرا

```bash
# ۱) نصب وابستگی‌ها
npm install            # یا: bun install

# ۲) متغیرهای محیطی (فایل .env از git حذف است؛ از نمونه بسازید)
cp .env.example .env   # سپس DATABASE_URL را تنظیم کنید

# ۳) دیتابیس (SQLite + Prisma) — فایل db/custom.db در ریپو هست؛ برای ساخت مجدد:
npx prisma generate
npm run db:push

# ۴) اجرای محیط توسعه (http://localhost:3000)
npm run dev            # یا: bun run dev
```

### Build و اجرای production

```bash
npm run build          # خروجی standalone + کپی static/public
npm run start          # اجرای سرور standalone روی همان اسکریپت پروژه
```

اسکریپت‌های دیگر: `npm run lint` (بررسی کیفیت کد)، `npm run db:generate`، `npm run db:migrate`، `npm run db:reset`.

**معماری: SPA تک‌مسیره.** در سطح URL فقط دو مسیر وجود دارد و «صفحات» اپ با روترِ داخلی stack (مبتنی بر zustand در `src/store/app-store.ts`) مدیریت می‌شوند — مطابق سند مرجع پروژه فقط `/` باید روت قابل‌مشاهده باشد.

### مسیرهای URL

| مسیر | توضیح |
| --- | --- |
| `/` | کل اپلیکیشن LiveShop (تمام ۲۶ صفحه از همین روت رندر می‌شوند) |

## 🛒 خرید با قیمت ثابت چطور کار می‌کند؟ (v1.4)

1. فروشنده در لایو «کالای در حال نمایش» را نشان می‌دهد (از داشبورد زنده پین می‌کند و کارت پایین برای همه با پیام چت «کالای جدید: …» عوض می‌شود).
2. خریدار دکمهٔ «خرید X تومان» را می‌زند → **شیت خرید سریع**: سایز/رنگ (موجودی جدا)، تعداد، آدرس، ارسال (تیپاکس/پست/پیک) و جمع کل.
3. «پرداخت» مبلغ را به‌صورت **امانی** از کیف پول کم می‌کند و سفارش می‌سازد — تایم‌لاین: «پرداخت امانی ← آماده‌ی ارسال ← ارسال‌شده ← تحویل ← آزادسازی پول».
4. کاهش موجودی با یک تابع واحد اتمیک (`purchaseItem` در `live-store.ts`) انجام می‌شود تا دو خرید هم‌زمان آخرین عدد را دوبار نفروشند؛ امضای تابع برای اتصال بعدی به API سمت سرور آماده است. ربات‌های شبیه‌ساز خریدار هم گاهی می‌خرند تا لایو زنده بماند.
5. کلید `AUCTION_ENABLED` در `src/lib/config.ts`: با `true` شدن، شیت بید، Max Bid، تایمر مزایده، پیل برندهٔ فعلی، تب بیدها، WinView و پیش‌بید دوباره فعال می‌شوند (کدشان پاک نشده).

## 🧪 داده‌ها — همه mock هستند

این پروژه **فقط فرانت‌اند دمو با دادهٔ mock** است؛ هیچ بک‌اند/درگاه پرداخت/لاجستیکی واقعی در کار نیست (زرین‌پال، آیدی‌پی و تیپاکس «شبیه‌سازی‌شده» هستند).

- **منبع اصلی دادهٔ mock:** پوشهٔ **`src/lib/data/`** — شوها و فروشنده‌ها (`shows.ts`)، آیتم‌ها (`items.ts`)، پیام‌های چت (`chat.ts`)، سفارش‌ها و روش‌های ارسال (`orders.ts`)، دسته‌بندی‌ها (`categories.ts`)، نقشهٔ عکس‌ها (`media.ts`) و دیتای فازها (`buyer-p1.ts`، `rewards-p1.ts`، `seller.ts`، `seller-analytics.ts`، `seller-marketing.ts`، `raid-p1.ts`، `types.ts`)
- **دیتابیس SQLite** (Prisma): فایل از قبل پرشدهٔ `db/custom.db` در ریپو هست؛ با `npm run db:push` از نو ساخته می‌شود
- استورهای کلاینتمد (zustand) در `src/store/` شروع‌به‌کار را با همین داده‌های mock انجام می‌دهند
